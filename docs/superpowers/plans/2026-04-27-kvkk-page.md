# KVKK Page Port — Plan

**Date:** 2026-04-27  
**Status:** Awaiting candidate decision

---

## Pre-flight Findings

The route already exists. No porting required. Key facts:

- `app/kvkk/page.tsx` — all 9 sections ported verbatim from production yikat.tech/kvkk
- `components/footer.tsx` — `/kvkk` link already present in "YASAL" column
- `app/mesafeli-satis-sozlesmesi/page.tsx` — established pattern: standalone sticky header (ArrowLeft + logo), `max-w-4xl`, `text-sm leading-relaxed sm:text-base`, `space-y-8`
- CSS tokens aligned: `--background: #FAFAF7`, `--foreground: #0F172A`, `--primary: #2798ff`
- No section `id` anchors on existing page
- Content is legally correct — verbatim fidelity must be preserved on any change

The question is not *how to port* but *what polish level to apply*.

---

## Candidates

### Candidate 1 — Ship As-Is

**Approach:** Declare victory. The page is complete, wired, and correct.

**Why it could be right:** Legal text is not a showcase surface. Readers visit once, scan for their article, leave. Optimizing this page returns near-zero value for the time spent.

**Trade-offs:**
- ✅ Zero risk of regression or content drift
- ✅ Zero LOC
- ❌ Body measure (`max-w-4xl` = 896px) is wider than comfortable long-read prose (~65ch / ~640px)
- ❌ Body size `text-sm` (14px mobile) is slightly small for dense legal text

**LOC delta:** 0

---

### Candidate 2 — Long-Read Typography ← **Recommended**

**Approach:** Improve reading comfort without touching content or structure. Three targeted changes to `app/kvkk/page.tsx`:

1. **Body size:** `text-sm leading-relaxed sm:text-base` → `text-base leading-relaxed sm:text-lg` — raises floor from 14px to 16px mobile, 16px to 18px desktop
2. **Measure:** `max-w-4xl` (896px) on `<main>` → `max-w-3xl` (768px) — tightens prose line to ~70–75ch, the optimal long-read sweet spot
3. **Section anchors:** Add `id="madde-N"` to each of the 9 `<section>` elements — enables deep-linking and future in-page navigation without adding any visible DOM

No new components. No client JS. Zero layout shift. Header stays `max-w-4xl` (wider container for the logo/back row looks intentional and balanced).

**Emil rationale:** Unseen details compound. A user reading through 9 dense legal sections will feel the difference between a 14px 896px-wide page and a 16px 768px-wide one — even if they never consciously notice the change. Narrower measure means fewer saccades, fewer re-finds of the left margin, less fatigue. This is the kind of detail that makes the whole brand feel more cared-for.

**Trade-offs:**
- ✅ Measurable readability improvement (measure + size are the two highest-leverage prose variables)
- ✅ Section anchors are free infrastructure — zero visible change, but enables shareable deep-links
- ✅ All changes in one file, ~10 LOC delta
- ❌ `sm:text-lg` (18px) is slightly large for dense nested lists — acceptable; legal text warrants generous sizing
- ❌ `max-w-3xl` header would look cramped — mitigated by keeping header at `max-w-4xl`

**LOC delta:** ~10

**Implementation plan:**

```
app/kvkk/page.tsx — only file touched

1. <main> measure: max-w-4xl → max-w-3xl
2. Body wrapper class: text-sm leading-relaxed sm:text-base
                     → text-base leading-relaxed sm:text-lg
3. Section anchors — add id="madde-1" through id="madde-9" on each <section>
   (existing sections already wrapped in <section> tags, just missing id attrs)
```

No new imports. No new components. No layout changes. Header measure stays `max-w-4xl`.

---

### Candidate 3 — Section Anchors + Back-to-Top Button

**Approach:** Add a floating "↑ Yukarı" back-to-top button that appears after scrolling past the header, plus the section anchors from Candidate 2.

**Why it could be right:** 9 sections of dense legal text — a user who scrolls to section 8 to find the contact channels will want a quick way back to top.

**Trade-offs:**
- ✅ Practical UX for a long page
- ❌ Requires a `"use client"` component for scroll detection (`useEffect` + `useState`)
- ❌ ~30–40 LOC new component + wiring
- ❌ Adds JS weight for a page with very low traffic
- ❌ Back-to-top is well-solved by browser native behavior (Home key, tap status bar on iOS) — adding our own is redundant in 2026

**LOC delta:** ~35–45

---

## Recommendation

**Candidate 2 — Long-Read Typography.**

The page already works. The only justified investment is the typography pass: it costs ~10 LOC and meaningfully improves a page dense enough to be worth reading comfortably. Section anchors are free future-proofing that adds zero weight.

Candidate 3's back-to-top button adds a client component to a server-rendered legal page for very marginal gain — browsers already handle this. Candidate 1 ships a page that's slightly uncomfortable to read at no cost saving (the work is trivial either way).

---

## Constraints

- Content must remain verbatim — no edits to Turkish legal text
- No layout shift
- No new client components unless user selects Candidate 3
- Header stays sticky — unchanged from current implementation
