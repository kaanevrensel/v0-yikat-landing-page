# Guide content batch: site structure, 2 November 2026

The November content programme adds about 60 new care guides, rewrites the 20 live guides and adds four
winter guides. This change prepares the site so a reviewed batch lands with one converter run plus the
test suite. The content plan and the writers' rules live outside this repository (scratchpad `plan/` and
`brief/RULES.md`); the decisions that shape the site are summarised here.

## Data and storage

- `CareGuide.topic` is required: one of six shoe topics or six textile topics (`lib/discovery.ts`). The
  type keeps textile guides informational: a `Tekstil` guide cannot carry a `service` link.
- `CareSection.links` accepts `{ type: "guide", slug, label }` besides photo and service links.
- One module per guide in `lib/guides/<slug>.ts`; `lib/guides/index.ts` holds `careGuides` in /rehber
  hub order and `guideRelease` (release date; guides added, rewritten, kept as live). `lib/care-sources.ts`
  holds every cited source. `lib/care-guides.ts` and `lib/discovery.ts` keep their exports.
- These files are generated by the content converter `json2ts.mjs` from reviewed JSON. Do not edit
  guide text by hand: change the JSON and run the converter again. Its README lists every check it makes.
- `lib/guide-topics.ts` (hand-written) holds topic anchors and hub intros. Intros describe the kind of
  problem rather than individual guides, so they stay true whichever guides of a topic are released.
  Textile intros are informational only.

## Pages

- Guide links render at the end of their section as one quiet line ("İlgili rehber: …"), like the source
  line: plain server-rendered `<a href="/rehber/<slug>">` with the visible label as the accessible name.
  Writers refer to them as being below the table or steps. Photo and service links stay the calls to action.
- /rehber stays one URL. An in-page index links the topic anchors; Ayakkabı and Tekstil blocks follow, one
  section per topic (H2, intro, anchor from the plan), pillars first. Topics with no released guide are
  omitted. Nothing sits above the H1; no tag, category, brand or district URLs; no new structured data.
- Service pages show the plan's guide rows inside existing sections with guide titles as anchors
  (`lib/service-guide-links.ts`); only released guides render. /bakirkoy-ayakkabi-temizleme keeps its two
  tested links. /ayakkabi-temizleme names the machine-washing guide by its title instead of "bakım rehberinde".

## Dates

- A guide's lastmod, Article `dateModified` and visible byline use `updated ?? published ?? CONTENT_DATE`.
  The former sitewide `CONTENT_UPDATED` floor is gone: link-only edits (related guides, guide links,
  service rows) never move a date.
- New guides are published on the release date. Rewrites keep their publication date and are updated on
  the release date. /rehber lastmod is the release date. Service pages keep their dates.
- Tests read `guideRelease`: a rewritten guide expects the release date as `dateModified`; an unchanged
  guide keeps its live date. Publication dates are asserted unchanged.

## Tests and CI

- `tests/guides.test.mjs` (Node, no browser) checks every related and guide-link slug, every source URL,
  topics, unique titles and descriptions, the word "tamir", shop links on textile guides and every value
  the renderer uses as a React key. It imports the TypeScript data through `tests/helpers/import-ts.mjs`.
- `tests/discovery.spec.ts` runs its route loops in fixed chunks (10 routes for layout and accessibility at
  four widths, 25 for canonical HTML), so per-test timeouts hold at about 150 routes and chunks spread across
  workers. CI keeps two workers; measured timings are in the commit that set them.
